Formal Grammars, Chomsky Hierarchy & Semi-Thue Rewriting Systems

This interactive reference guide outlines the mathematical foundations of formal grammars, generative rewriting rules, the Chomsky Hierarchy (Types 0 through 3), and non-deterministic search algorithms used for parsing and string recognition.

1. The Chomsky Hierarchy (Language Inclusion: L₃ ⊂ L₂ ⊂ L₁ ⊂ L₀)

Introduced by Noam Chomsky in 1956, formal grammars are classified into four hierarchical tiers based on the strictness of constraints imposed on their production rules. Every tier strictly contains the languages generated by the tier below it:

Tier Grammar Type Rule Production Form Recognizing Automaton Parsing Complexity Word Problem
Type-3 Regular A → wB or A → w (Right-Linear)
A → Bw or A → w (Left-Linear)		 Finite State Automaton (DFA / NFA) Linear: O(n) Decidable
Type-2 Context-Free (CFG) A → γ where A ∈ V_N, γ ∈ (V_N ∪ Σ)* Pushdown Automaton (PDA) Polynomial: O(n³) (CYK/Earley) Decidable
Type-1 Context-Sensitive (CSG) α → β with |α| ≤ |β| (Non-contracting) Linear Bounded Automaton (LBA) PSPACE-complete Decidable
Type-0 Unrestricted / Semi-Thue α → β (Arbitrary rewriting, α ≠ ε) Turing Machine Undecidable Recursively Enumerable

2. Detailed Tier Specifications & Interactive Presets

Type-3: Regular Grammars

Regular grammars generate regular languages. Every production rule must be strictly Right-Linear (a non-terminal appears only at the extreme right of RHS) or Left-Linear (a non-terminal appears only at the extreme left of RHS).

Canonical Example: Alternating tokens (ab)⁺:

S → aA, A → bS, A → b

Type-2: Context-Free Grammars (CFG)

In CFGs, the Left-Hand Side (LHS) of every production rule consists of a single isolated non-terminal symbol (|LHS| = 1). The replacement can take place regardless of the symbols surrounding it (hence "context-free").

Canonical Example 1: Non-regular matching language { aⁿbⁿ | n ≥ 0 }:

S → aSb | ε

Canonical Example 2: Dyck Language (Balanced Parentheses):

S → (S)S | ε

Type-1: Context-Sensitive Grammars (CSG)

In Context-Sensitive Grammars (monotonic/non-contracting formulation), for every rule α → β, the length of the RHS must be greater than or equal to the LHS (|α| ≤ |β|). This guarantees that during derivation, strings never shrink (except for the special case of an axiom deriving empty string S → ε where S does not appear on any RHS).

Canonical Example: The three-count non-context-free language { aⁿbⁿcⁿ | n ≥ 1 }:

S → aSBC | aBC, CB → BC, aB → ab, bB → bb, bC → bc, cC → cc

Type-0: Semi-Thue Systems & Unrestricted Grammars

Axel Thue introduced Semi-Thue systems in 1914 as a formal framework for string rewriting. A Semi-Thue system consists of a finite alphabet Σ and a set of directed replacement rules u → v. Unlike formal grammars, Semi-Thue systems make no fundamental distinction between terminals and non-terminals.

Type-0 systems are computationally Turing-complete. Any algorithm computable by a Turing Machine can be simulated by string replacements in a Semi-Thue system.

Canonical Example: Ripple-Carry Binary Incrementer (>1011+ → 1100):

0+ → 1, 1+ → +0, >+ → >1, > → ε

3. Algorithm & Search Theory

Breadth-First Search (BFS) vs. Depth-First Search (DFS)

When searching for a derivation of target string w from start symbol S:

  • Why BFS is required: BFS explores the search tree level by level. Because each step represents one rule substitution, BFS is guaranteed to discover the shortest possible derivation sequence (minimal number of steps).
  • Why DFS fails in rewriting systems: Even simple rules such as S → aSb or A → B, B → A create infinite paths. DFS can dive infinitely deep down a non-terminating branch and fail to find a valid finite derivation that exists just one branch over.

The Undecidability Problem & Safety Limits

For general Type-0 grammars and Semi-Thue systems, the Word Problem (determining whether a given string w can be derived from start axiom S) is undecidable. This is directly related to Alan Turing's Halting Problem.

Because arbitrary rules can contract string lengths (e.g. abc → a), the search space can expand and contract indefinitely. No algorithm can determine in finite time whether an arbitrary Type-0 derivation will terminate or loop forever. For this reason, production visualizers implement strict Max Search Depth and Max Visited Nodes safety caps.

Monotonic Length Pruning

In Type-1 (Context-Sensitive), Type-2 (without ε-rules), and Type-3 grammars where every production rule satisfies |LHS| ≤ |RHS|, the length of the derived string is monotonically non-decreasing:

|S₀| ≤ |S₁| ≤ |S₂| ≤ ... ≤ |S_k|

Therefore, if at any point |S_current| > |w_target|, that branch can never shrink back down to match w_target. The visualizer's BFS engine automatically detects this condition and immediately prunes such candidate nodes, cutting exponential branching by up to 90%!
